# PReOF E2 — layer-wise enhancement-induced representation drift

**Status: exploratory protocol and code; no real E2 result has been generated locally.** E0 and E1 were completed on KC validation data. The operator reported that E0 did not show convincing incremental AUPRC from cross-preprocessing response beyond native expert disagreement. In E1, native-to-cross accuracy fell from 0.7923 to 0.3716 (APTOS V1), 0.8142 to 0.3743 (APTOS V2), 0.7859 to 0.2220 (DDR V1), and 0.8299 to 0.2316 (DDR V2). These rounded values and the statement that all four paired accuracy-degradation intervals exclude zero are **operator-reported**, not recalculated from KC files here. No lesion destruction or clinical mechanism follows from them.

## 1. Fixed source and feature points

The historical [`CADViTCandidate`](../reproduction/cadvit/model.py) is imported without editing it. The existing Phase 1 `checked_models` guard checks each dataset's V1/V2 checkpoint hashes, records, model/preprocessing source, strict state compatibility, and V2 notebook definitions before frozen inference. The feature hooks use the audited `stem`, `blocks[3]` (`IRB+A-2`), `blocks[8]` (`EMB-3`), and `head`. At 512×512 input their outputs are respectively `[B,32,256,256]`, `[B,96,64,64]`, `[B,160,16,16]`, and `[B,320,16,16]`. The selected levels cover early, intermediate, deep, and pre-classifier representations. Each hook applies the model's adaptive average pool to 1×1 immediately; only 32-, 96-, 160-, and 320-dimensional `float32` vectors are transferred to CPU. Full spatial maps are transient and never cached. The model remains in `eval()` and `torch.inference_mode()` with parameter gradients disabled; there is no augmentation, optimizer step, or batch-normalization update.

For each validation image E2 reads V1 and V2 BG10 deterministic arrays from the **existing shared preprocessing cache**. E2 requires verified hits; a missing or corrupt entry stops the run for investigation and is not regenerated by E2, preserving Phase 1 cache bytes. Both fixed models receive both arrays, producing `p11`, `p12`, `p21`, and `p22` in the Phase 1 order. Before storing that image's four vectors, E2 compares all four extracted logit vectors with the complete existing Phase 1 prediction cache. Default `atol=rtol=1e-4` accommodates small FP32 kernel/device differences while rejecting material output changes; the CLI rejects non-finite tolerances or values above `1e-3`. Exact tolerances and runtime are stored in metadata. A mismatch stops extraction. Do not widen tolerances just to obtain a pass: inspect preprocessing version, device precision, checkpoint identity, and logits first.

## 2. Feature cache and storage

Only frozen-manifest `split=val` rows are eligible: APTOS2019 **366**, DDR **1,252**. The feature root must be outside Git, raw datasets, and the prediction/preprocessing cache roots. Each image has one lossless `.npy` array of shape `[4,608]`, `float32`, plus an indexed `rows.jsonl` record. The raw vector payload is **9,728 bytes/image**: approximately **3.40 MiB** for APTOS, **11.62 MiB** for DDR, **15.01 MiB combined**, plus NPY headers, JSONL, and metadata. This is a capacity estimate, not measured KC disk use. Two dataset jobs use separate feature output directories and may share the compatible preprocessing cache.

`metadata.json` records the manifest and prediction-cache hashes, checkpoint and source hashes, model/preprocessing condition order, feature layers, pooling, shape, dtype, runtime, logit tolerance, and E2 implementation SHA-256. A separate fingerprint of the extractor AST and feature specification controls cache compatibility, so a later edit to analysis prose or plotting alone does not invalidate pooled features. Each `rows.jsonl` record binds image ID/grade/group/source SHA to a feature key and `.npy` SHA-256. Feature files are written through unique temporary files, `fsync`, then atomic replacement; the index row is appended and `fsync`ed after all four logit checks. Resume validates the entire prefix and every array checksum/shape/dtype/finite value. A corrupt file fails closed for investigation; E2 never silently reuses or deletes it. A completed cache exits before checkpoint loading or inference. Smoke and full runs require separate output directories, since their metadata has different image counts.

## 3. Exploratory CPU analysis

[`preof_e2.py`](../novelty/preof_e2.py) `analyze` reads the full verified feature and prediction caches without images, GPU, or models. Within **each fixed model**, it compares native versus cross-preprocessing pooled vectors at all four layers. Per-image metrics are `1−cosine` and `||native−cross||₂ / ((||native||₂+||cross||₂)/2)`; both-zero vectors map to zero. Centered **linear CKA** summarizes each paired validation cohort, not individual images. Tables retain grade support, mean/median drift, correct→wrong and wrong→correct transitions, and Spearman association of drift with **cross minus native absolute grade error**. Paired `group_id` bootstrap intervals describe mean drift and association; small or constant samples can yield unestimable correlations.

The incremental test reuses the E0 native-boundary error target `P(Y≥k)≥0.5` and prediction-only feature set **B** (native confidence/entropy plus native-expert disagreement). **D**, containing all four distributions, is a stronger prediction-only reference. Each layer adds exactly two drift features to B. `B+random2` matches that extra dimension; `B+all_layers` and `B+random8` each add eight dimensions; `D+all_layers` checks whether drift adds information beyond all prediction distributions. Random columns are one fixed label-independent Gaussian draw, not a distribution over random seeds. The estimator is the existing fixed L2 logistic model, standardized on **training folds only**, with one grouped fold assignment shared across all conditions. All four boundaries, both models, and all layers are reported. Paired group-bootstrap intervals compare OOF AUROC/AUPRC/Brier/log loss; no held-out fold is used for feature scaling or model selection.

Outputs per dataset: `e2_results.json`, `e2_report.md`, `cosine_profile.svg`, `normalized_l2_profile.svg`, `linear_cka_profile.svg`, `per_grade_drift.svg`, and `incremental_auprc.svg`. SVG figures and machine-readable JSON are generated from the **actual** KC cache when the manual commands run. No real E2 plot or score is claimed here. The analysis is exploratory with many correlated layer/boundary comparisons; selecting the largest delta would require a separate prespecified confirmation. Bootstrap intervals condition on the fixed out-of-fold predictions and do not refit the estimator in each bootstrap sample. A stable feature need not be diagnostically useful, and representational change cannot by itself establish lesion loss or clinical causation. The prior E0 NO-GO for M2–M4 remains in force. No severity-subspace method, selective alignment, PEFT, or new architecture is implemented.

## 4. Manual KC execution

Run only after the reviewed `novelty/preof_e2.py` and project source are available on the KC **novelty** checkout. These commands do not rerun final test or train. Set the existing paths once per terminal:

```bash
ROOT="$HOME/Kel_13"
REPO="$ROOT/Diabetic-Rethinography"
PY="$ROOT/.venv/bin/python"
V2_SOURCE="$ROOT/Diabetic-Rethinography-v2/CAD_ViT.ipynb"
PREPROCESS_CACHE="$ROOT/preof_phase1/preprocessing"
cd "$REPO"
test "$(git branch --show-current)" = novelty || { echo 'Use the novelty checkout'; exit 1; }
test -f novelty/preof_e2.py && test -f "$V2_SOURCE" || { echo 'Required source missing'; exit 1; }
```

**Smoke, GPU 0 / APTOS:**

```bash
CUDA_VISIBLE_DEVICES=0 "$PY" -m novelty.preof_e2 extract --dataset APTOS2019 --artifact-root "$ROOT" --prediction-cache-dir "$ROOT/preof_phase1/aptos_full" --preprocess-cache-root "$PREPROCESS_CACHE" --v2-source "$V2_SOURCE" --trust-checkpoints --device cuda:0 --limit 3 --output-dir "$ROOT/preof_e2/aptos_smoke"
```

**Smoke, GPU 1 / DDR (separate terminal, with the same environment variables above):**

```bash
CUDA_VISIBLE_DEVICES=1 "$PY" -m novelty.preof_e2 extract --dataset DDR --artifact-root "$ROOT" --prediction-cache-dir "$ROOT/preof_phase1/ddr_full" --preprocess-cache-root "$PREPROCESS_CACHE" --v2-source "$V2_SOURCE" --trust-checkpoints --device cuda:0 --limit 3 --output-dir "$ROOT/preof_e2/ddr_smoke"
```

Inspect smoke metadata, `rows.jsonl`, and the maximum absolute logit differences before full extraction. **Full APTOS / DDR:**

```bash
CUDA_VISIBLE_DEVICES=0 "$PY" -m novelty.preof_e2 extract --dataset APTOS2019 --artifact-root "$ROOT" --prediction-cache-dir "$ROOT/preof_phase1/aptos_full" --preprocess-cache-root "$PREPROCESS_CACHE" --v2-source "$V2_SOURCE" --trust-checkpoints --device cuda:0 --output-dir "$ROOT/preof_e2/aptos_full"
CUDA_VISIBLE_DEVICES=1 "$PY" -m novelty.preof_e2 extract --dataset DDR --artifact-root "$ROOT" --prediction-cache-dir "$ROOT/preof_phase1/ddr_full" --preprocess-cache-root "$PREPROCESS_CACHE" --v2-source "$V2_SOURCE" --trust-checkpoints --device cuda:0 --output-dir "$ROOT/preof_e2/ddr_full"
```

Run the two full commands in **different terminals** with the same environment setup. If interrupted, rerun the identical command for the same dataset/output directory with `--resume`. Do not use the smoke output as the full cache. Once both full caches pass validation, perform CPU analysis:

```bash
"$PY" -m novelty.preof_e2 analyze --dataset APTOS2019 --artifact-root "$ROOT" --prediction-cache-dir "$ROOT/preof_phase1/aptos_full" --feature-cache-dir "$ROOT/preof_e2/aptos_full" --output-dir "$ROOT/preof_e2/aptos_analysis" --folds 5 --bootstrap 500 --seed 42
"$PY" -m novelty.preof_e2 analyze --dataset DDR --artifact-root "$ROOT" --prediction-cache-dir "$ROOT/preof_phase1/ddr_full" --feature-cache-dir "$ROOT/preof_e2/ddr_full" --output-dir "$ROOT/preof_e2/ddr_analysis" --folds 5 --bootstrap 500 --seed 42
```

The analysis requires a complete feature cache and refuses to overwrite an existing output directory. All results must be reviewed as exploratory; any candidate methodological contribution would first require a targeted prior-art audit and a distinct confirmation plan.
