### Structured pruning details

- **V2** (cells 42, 43, 47). Rank expansion channels by the L1 norm of the rows of the first linear projection. Construct smaller `fc1`, select the matching GRN scale/bias channels and select columns of `fc2`. Output width and residual stay fixed. GRN's response normalization still depends on retained channels, so slicing its parameters does not guarantee equivalence to the unpruned graph. The 10%, 30% and 50% sweep starts each candidate from the original state, uses three recovery epochs by default with ordinary CE and AdamW, and selects by validation macro-F1, but also evaluates test before and after recovery. It saves a full Python model object to encode new widths. The longer 50% cell has a different recovery budget and belongs to a separate comparison.
- **HF V1** (cells 24 and 29). Rank rows of `pwconv1` in `backbone.encoder.stages[*].layers[*]`, slice its bias, then take the matching `pwconv2` input columns. There is no GRN. The output-facing layer scale and residual dimensions remain intact. The default 10/30/50% sweep starts from a fresh checkpoint load, uses three recovery epochs, and uses the E5 auxiliary head with B1 augmentation. It passes `class_weights=None` throughout the recovery. That is an unweighted recovery schedule, not evidence that the original delayed-weight trajectory continued. The saved narrowed backbone needs explicit reconstruction of each layer width before strict state loading. The notebook records parameter counts and elapsed backend timings. It does not provide paired, quality-preserving FLOP and latency evidence for the original frozen runs.

For either family, L1 ranks expansion channels within a block and does not measure global importance. Exact per-layer retained widths must account for rounding and any documented vector alignment. For two dense projections of width `d -> h -> d` at feature grid `H×W`, the projection MAC delta for removing `r` channels is `2 × H × W × d × r` per image. It excludes depthwise convolution, normalization, GRN, gates, activations, memory traffic and backend overhead. Report FLOP convention explicitly if counting one multiply-accumulate as two operations. E7 uses the sum over its one global and two local grids, while storing/counting the shared backbone parameters once. ## Structured pruning compatibility on salma

| Experiment | Possible topology-preserving surgery | Recovery and evidence gate |
| --- | --- | --- |
| B0 | HF expansion only. Leave output width, head and processor unchanged. | Ordinary CE, no augmentation. Pin exact historical checkpoint and source. |
| B1 | Same HF expansion. | Ordinary CE, original B1 train-only augmentation and deterministic validation. |
| B2 | Same HF expansion. | Retain the recorded train-only weighting formula if testing protocol-preserving recovery, or predeclare unweighted recovery as a different arm. |
| B3 | Same surgery only after strict verification of the original topology. | Require the external grade 3 sampler/runner and their hashes for faithful recovery. Never silently substitute B1. |
| B4 | Same surgery for APTOS Q and R separately. DDR is inapplicable. | Require external B4 selection, cache, augmentation and runner evidence. Preserve the two distinct train selection digests. |
| E5 | HF expansion with both heads retained through recovery. | Use the E5 ordinal loss and a prespecified recovery weighting schedule. Report the historical unweighted recovery as a different variant. |
| E6 | HF expansion with identical pre/post inference head. | Preserve LDAM, adjacent-grade and ordinal objective, train counts, margin/weight computation and explicit recovery schedule. The E5 recovery function would discard E6 terms. |
| E7 | Prune the single *shared* backbone once. Keep 768-dimensional pooled width, 384/224 views, two patches, gate and heads. | Verify both shapes and memory/compute. Recovery must use E7 collation, objective and selected raw/EMA policy. Require genuine E7 checkpoint and receipts before a run. |

The common safe operation is to verify the original digest, instantiate/load the exact parent, and create a derived copy with a new external name and checksum. Persist retained indices, topology, shape/config metadata, source/processor/manifest hashes, and state dict. Reconstruct the smaller topology before strict load. Check weight device and dtype and only then build the new optimizer. Preserve immutable parent hashes after export and recovery. No in-place mutation of an original stored checkpoint is needed.

## Proposed optimization protocol

1. **A. Native parent reference.** Register dataset, family, original best epoch and checksum, class order, original manifest SHA, preprocessing/augmentation source, dataset-specific subsets and ordered sample/tensor digests. Keep raw checkpoint and official processor read-only. Record baseline logits, argmax labels, quality metrics and confusion on the same fixed validation subset used for later comparisons. Distinguish the archived full-validation result from this new subset estimate. Prefer an approved independent non-test optimization split where available and document group isolation.
2. **B. Backend-only optimization.** Export from a verified disposable model with no retraining. Use identical FP32 tensors, explicit eval mode, aligned output shapes and both logit-error and argmax agreement checks. Decide tolerances before measuring (for example, close FP32 logits and review every changed prediction). Record confusion and per-grade recall on identical examples. Freeze hashes of split membership, ordered indices, code and preprocessing. Report CPU model and architecture, OS, package versions, core affinity, threads, dtype, runtime settings, operator/provider fallbacks, OpenVINO compile mode and ORT graph setup. Benchmark batch 1 synchronous request latency with a fixed 20 warm-ups and at least three independent measured repetitions in controlled process order. Report p50/p95 and per-repeat total examples/elapsed time. Separately measure deployment batch throughput, preprocessing-only, end-to-end (decode/transforms plus inference) and cold startup; the stages answer different questions.
3. **C. Pruning and recovery.** Prespecify L1 per expansion unit, rounding and 10%, 30%, 50% target removal. Add a 0% recovery control so pruning loss and recovery effects can be separated. Record actual channels removed, parameter counts and projection MACs by stage/grid. Test each pruned copy before recovery. Use a common bounded budget (e.g., three epochs), matched seeding, train-only updates and family-specific loss/augmentation. Choose by non-test macro-F1 with prespecified tie breaks and record epoch zero through recovery. Report exact seeds, unsuccessful arms and failures. Certify parent artifacts remain identical.
4. **D. Post-recovery review.** Evaluate all selected copies on the exact same ordered, authorized non-test quality set as A. First compare eager pre/post pruning; then re-check backend parity and latency on the chosen copies under B. Report paired prediction differences, uncertainty when enough independent groups exist, and the efficiency/quality trade-off, including minority grades. If the same validation rows select ratios, checkpoints or backends and assess them, mark the conclusion as exploratory with selection bias. Keep official frozen test sealed. Record independent evaluation only when an untouched split and authorization exist.

An optimized derivative remains identified by its parent experiment, dataset, backend/pruning treatment, and budget. Smaller parameter count or an estimated MAC reduction does not establish a speedup or a quality improvement.
